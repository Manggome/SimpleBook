# 심플북 (SimpleBook)

폰에 있는 만화·책 파일을 폴더째 등록해서 읽는 안드로이드 뷰어.

**[📥 최신 APK 받기](https://github.com/Manggome/SimpleBook/releases/latest/download/SimpleBook.apk)** — 폰에서 이 링크를 누르면 바로 설치됩니다.

- UI: Kotlin + Jetpack Compose (Material 3)
- 최소 안드로이드 7.0 (API 24)
- 갤럭시 Z 폴드처럼 접었다 펴는 화면을 기준으로 만들었습니다

---

## 읽을 수 있는 것

| 형식 | 상태 | 비고 |
|---|---|---|
| ZIP · CBZ | ✅ | 중앙 디렉터리를 직접 읽어 임의 페이지로 바로 점프 |
| 이미지 폴더 | ✅ | 폴더 안에 이미지가 있고 하위 폴더가 없으면 그 폴더가 한 권 |
| PDF | ✅ | 안드로이드 기본 렌더러. 암호 걸린 PDF 는 불가 |
| TXT | ✅ | UTF-8 / CP949 자동 판별, 쪽 나눔 + 본문 검색 |
| RAR · CBR (RAR4) | ✅ | 캐시에 한 번 복사한 뒤 읽음 |
| RAR5 | ❌ | 자바로 쓸 수 있는 무료 구현이 없습니다. ZIP/CBZ 로 다시 묶어 주세요 |
| EPUB | ⏳ | 아직. `BookSource` 만 구현하면 뷰어는 손대지 않아도 붙습니다 |

## 책장

**폴더를 등록하면 폴더가 그대로 한 칸이 됩니다.** 눌러서 들어가면 그 안의 파일이 다시 목록으로 나옵니다. 파일 하나만 골라 넣으면 최상위에 그대로 놓입니다.

- **보기** — 표지 격자 / 목록 줄 (오른쪽 위 아이콘으로 전환)
- **정렬** — 읽은순(최근에 읽은 것이 위, 안 읽은 책은 제목순으로 뒤에) / 제목순
- 파일 이름은 `1, 2, 10` 을 사람이 기대하는 순서로 정렬합니다
- 읽은 비율이 **막대 그래프**와 퍼센트로 표시됩니다. 다 읽으면 "완독"
- 표지는 첫 페이지를 뽑아 캐시에 남깁니다. 목록도 캐시해서 두 번째부터는 바로 뜹니다
- **표지를 직접 바꿀 수 있습니다.** 항목을 길게 눌러 `표지 바꾸기`. 폴더에도 지정할 수 있고, 캐시를 비워도 지워지지 않습니다 (`표지 되돌리기` 로 원상복구)

원본은 건드리지 않습니다. 안드로이드 폴더 선택(SAF)으로 읽기 권한만 영구 저장하고, 파일은 있던 자리에 그대로 둡니다. 책장에서 빼도 폰의 파일은 지워지지 않습니다.

## 읽기

**넘기는 방향** — 세 가지 중에서 고릅니다.

| | 진행 | 다음 쪽으로 |
|---|---|---|
| 한국식 (좌철) | 왼쪽 → 오른쪽 | 화면 **오른쪽 25%** 탭, 또는 왼쪽으로 드래그 |
| 일본식 (우철) | 오른쪽 → 왼쪽 | 화면 **왼쪽 25%** 탭, 또는 오른쪽으로 드래그 |
| 세로 스크롤 | 위 → 아래 | 그냥 스크롤 |

2쪽 보기에서도 같은 규칙이 적용됩니다. 일본식이면 먼저 나오는 쪽이 **오른쪽**에 붙습니다.

**터치 영역은 좌 25% / 가운데 50% / 우 25%** 입니다. 가운데를 누르면 메뉴가 열립니다.

**넘김 효과** 는 `슬라이드`(페이지가 손가락을 따라옴)와 `없음`(놓는 순간 즉시 교체) 중에서 고릅니다.

**1쪽 / 2쪽** — 기본은 `자동` 입니다.

접힘 상태를 직접 읽지 않고 **화면의 가로÷세로 비율**로 판단합니다. 기준값(기본 0.85) 이상이면 2쪽을 폅니다. 접힘·펼침·가로·세로 네 가지 조합이 규칙 하나로 다 풀리기 때문입니다.

| 폴드 상태 | 화면 비율 | 기본값(0.85) |
|---|---|---|
| 접고 세로 | ~0.41 | 1쪽 |
| 접고 가로 | ~2.4 | 2쪽 |
| 펴고 세로 | ~0.86 | 2쪽 |
| 펴고 가로 | ~1.16 | 2쪽 |

기준값은 `설정 > 2쪽으로 바뀌는 기준` 에서 조절합니다. 1.00 으로 올리면 "펴고 가로" 에서만 2쪽이 됩니다. 자동이 마음에 안 들면 `1쪽 고정` / `2쪽 고정` 으로 못 박을 수 있고, 이건 **책마다 따로** 저장됩니다 (읽는 화면의 ⚙︎). 전체 기본값으로 올리려면 같은 화면의 `모든 책의 기본값으로 저장`.

**표지는 혼자 두기** — 2쪽 보기에서 1쪽만 단독으로 띄웁니다. 표지가 오른쪽 페이지와 붙어 버리면 그 뒤 모든 펼침면이 한 장씩 밀리기 때문입니다.

그 외

- 접었다 펴도 **보고 있던 페이지를 그대로** 따라갑니다
- 화면 가운데를 탭하면 위/아래 메뉴가 나옵니다. 슬라이더로 쪽 이동
- 손가락 두 개로 확대(최대 5배), 확대 중에는 페이지 넘김이 멈춥니다
- 읽던 쪽은 자동 저장되고 다음에 그 자리에서 이어집니다
- **마지막 쪽에서 한 번 더 넘기면** `다음 화`(같은 폴더의 이름순 다음 파일)와 `책장으로` 가 뜹니다

### TXT

- **읽기 방식** 을 `스크롤` / `책 넘김` 중에서 고릅니다 (읽는 화면의 ⚙︎)
- **본문 검색** — 위쪽 🔍 로 찾고, 결과를 누르면 그 쪽으로 뛰며 형광펜이 남습니다
- 글자 크기 조절, UTF-8 / CP949 자동 판별

스크롤 모드도 쪽 단위로 잘라 목록으로 그립니다. 소설 한 권을 통짜 텍스트로 그리면 스크롤이 버벅이고, 검색 결과로 정확히 뛸 수도 없기 때문입니다.

### 화면

`설정 > 화면` 에서 회전(자동 / 세로 고정 / 가로 고정)과 앱 밝기를 잡습니다. 밝기는 기본이 시스템 연동이고, 체크를 끄면 이 앱에서만 따로 씁니다.

패치노트는 `설정 > 패치노트` 에 들어 있습니다.

## 빌드 / 업데이트

push 하면 GitHub Actions 가 자동으로 빌드해서 `latest` 릴리스를 갱신합니다.

- 서명 키는 `keystore/debug.jks` 로 저장소에 고정돼 있습니다. 없으면 CI 가 한 번 만들어 커밋합니다. 빌드마다 키가 바뀌면 덮어쓰기 설치가 안 되기 때문입니다.
- 정식 서명이 필요하면 [make-keystore 워크플로](../../actions/workflows/make-keystore.yml)로 키를 만들고 `KEYSTORE_B64` / `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD` 시크릿을 등록하세요.
- 버전은 CI 실행번호로 매겨집니다 (`1.0.<run_number>`). 릴리스에 `latest.json` 이 함께 올라가고 앱이 이것과 자기 버전을 비교합니다.
- 앱은 시작할 때 조용히 새 버전을 확인하고, 있으면 물어본 뒤 받아서 설치까지 이어줍니다. `설정 > 앱 업데이트` 에서 직접 확인할 수도 있습니다.
- 빌드가 실패하면 원인이 실행 요약 페이지와 `ci-logs` 브랜치(`last-failure.txt`)에 자동으로 발행됩니다.

### 알아두면 도움되는 설계 결정

**ZIP 을 직접 파싱합니다.** `java.util.zip.ZipFile` 은 실제 파일 경로를 요구하는데 SAF uri 에는 경로가 없습니다. `ZipInputStream` 은 앞에서부터 순차로만 읽혀서 300 페이지 책의 뒤쪽을 펴려면 앞을 전부 통과해야 합니다. 그래서 중앙 디렉터리를 읽어 임의 접근을 만들었습니다. 파일명이 CP949 인 한국 압축 파일도 여기서 처리합니다.

**`DocumentFile` 대신 `ContentResolver` 를 직접 씁니다.** `DocumentFile.listFiles()` 는 항목마다 별도 질의를 날려서 수백 개짜리 폴더에서 몇 초씩 걸립니다.

**접힘 센서 대신 화면 비율을 봅니다.** Jetpack WindowManager 로 힌지를 읽으면 "펴고 세로" 에서 페이지가 세로로 길쭉해집니다. 비율로 보면 네 가지 조합이 규칙 하나로 풀리고, 태블릿·데스크톱 창 모드에도 그대로 맞습니다.

**손동작 감지기는 콘텐츠 위에 덮지 않고 같은 modifier 사슬에 답니다.** 페이저 위에 투명 레이어를 올리면 Compose 의 히트 테스트가 그 레이어에서 멈춰서 드래그와 스크롤이 전부 거기 먹힙니다. 같은 사슬에 달면 안쪽 스크롤이 드래그를 먼저 가져가고 탭만 바깥으로 내려옵니다.

**페이지는 화면 크기에 맞춰 줄여서 디코딩합니다.** 만화 원본은 한 장이 2000x3000 을 넘는 일이 흔합니다. 화면 크기가 바뀌면 캐시를 비우고 새 크기로 다시 그립니다 — 줄여 놓은 것을 늘려 쓰면 글씨가 뭉개지기 때문입니다.
